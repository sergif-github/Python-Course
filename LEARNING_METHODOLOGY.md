# Методология обучения

Курс рассчитан на последовательное изучение Python с одним 90-минутным занятием в неделю. Каждый модуль сочетает теорию, примеры, отдельные упражнения и небольшой этап учебного проекта.

Главный принцип курса: условия проектных этапов находятся в соответствующих учебных модулях, а развивающийся код хранится централизованно в папке [`Projects`](./Projects/). Студент видит, как программа постепенно усложняется, и работает с одной актуальной версией каждого проекта.

## Учебный цикл модуля

Каждый модуль проходит по одной последовательности:

```text
Теория
→ примеры
→ отдельные упражнения
→ разбор решений
→ базовый этап проекта
→ продвинутый этап проекта
→ проверка на следующем занятии
```

Базовый этап закрепляет обязательный материал модуля. Продвинутый этап добавляет граничные случаи, более сложный алгоритм или дополнительную возможность проекта.

## Рекомендуемый темп курса

Один учебный модуль не всегда соответствует одному занятию. Проектное задание выполняется на завершающем занятии модуля после изучения необходимой теории.

| Модуль | Рекомендуемое число занятий |
| --- | ---: |
| 0. Введение в Python | 1 |
| 1. Переменные и типы данных | 2 |
| 2. Операторы | 1 |
| 3. Управление потоком выполнения | 1 |
| 4. Циклы | 1 |
| 5. Методы и функции | 2 |
| 6. Объектно-ориентированное программирование | 2 |
| 7. Обработка исключений | 1 |
| 8. Модули, пакеты и библиотеки | 1 |
| 9. Работа с файлами | 2 |
| 10. Дополнительные модули Python | 2–3 |

| 12. Тестирование и отладка | 2 |

Полный курс рассчитан приблизительно на 20–22 еженедельных занятия. Точный темп зависит от начального уровня группы и объёма продвинутых заданий.

## Как будет выглядеть занятие

| Этап | Время |
| --- | ---: |
| Короткая проверка предыдущего задания | 10 минут |
| Теория нового модуля | 20 минут |
| Примеры вместе с преподавателем | 15 минут |
| Обычные упражнения | 20 минут |
| Начало нового этапа проекта | 20 минут |
| Обсуждение домашнего задания | 5 минут |

На занятии преподаватель показывает начало проектного этапа и помогает определить структуру решения. Базовую реализацию студент завершает дома. Продвинутую задачу можно начать на занятии при уверенном темпе группы.

## Домашняя работа

Домашняя работа состоит из двух частей:

- **базовый уровень** обязателен и добавляет основную возможность проекта;
- **продвинутый уровень** даёт дополнительные баллы и добавляет обработку сложных случаев.

Каждое проектное задание должно содержать:

- ссылку на рабочий файл проекта;
- перечень функций или классов для реализации;
- пример входных данных;
- ожидаемый результат;
- критерии завершения;
- открытую проверку, когда материал модуля позволяет её использовать.

## Как проверять проект

В каждом проектном задании используются четыре вида проверки.

### Открытые тесты

Студент запускает их самостоятельно:

```python
assert calculate_word_frequency("a b a") == {
    "a": 2,
    "b": 1,
}
```

Открытые тесты помогают проверить основной сценарий и понять ожидаемый формат результата.

### Дополнительные тесты преподавателя

Они проверяют:

- пустые данные;
- неверные данные;
- граничные значения;
- несколько вариантов входных данных;
- отсутствие нежелательных изменений в уже реализованных возможностях.

Студент заранее знает категории проверок, но не конкретные значения дополнительных тестов.

### Короткая проверочная задача

В начале следующего занятия студент решает похожую задачу с другими данными:

```python
words = ["python", "java", "python", "c++", "java", "python"]

# Постройте частотный словарь без использования list.count().
```

Такая задача показывает, может ли студент самостоятельно применить изученный приём.

### Объяснение собственного кода

Студент должен объяснить:

- что получает функция;
- что она возвращает;
- как работает основной алгоритм;
- какие ошибки обрабатываются;
- почему выбрана конкретная структура данных;
- какие граничные случаи были учтены.

## Что делать с существующими упражнениями и решениями

Существующие файлы сохраняют свою роль:

```text
06_exercises.ipynb
07_solutions.ipynb
```

Они используются для практики отдельных конструкций Python. Упражнение может быть полностью закончено внутри одного ноутбука и не обязано изменять учебный проект.

Существующие итоговые проекты «Оценки», «Банк» и «Интернет-магазин» сохраняются как дополнительные задания. Основная последовательность курса определяется четырьмя проектами из папки `Projects`.

Проектные задания отвечают за перенос изученных конструкций в полноценную программу. В текущей структуре каждого модуля они собраны в одном файле:

```text
project_tasks.md
```

Внутри него находятся базовый и продвинутый уровни. Сам код студент изменяет в соответствующей папке `Projects`.

Пример структуры модуля:

```text
04-Loops/
├── 01_while_loop.ipynb
├── 02_for_loop.ipynb
├── 03_loop_control_statements.ipynb
├── 04_nested_loops.ipynb
├── 05_looping_collections.ipynb
├── 06_exercises.ipynb
├── 07_solutions.ipynb
└── project_tasks.md
```

Такой формат сохраняет компактную структуру курса. Если проектному этапу впоследствии понадобятся исполняемые ячейки, его можно перенести в два ноутбука:

```text
08_project_homework_base.ipynb
09_project_homework_advanced.ipynb
```

## Последовательность проектов

1. **Калькулятор** развивается в модулях 0–5 и становится первым завершённым проектом.
2. **Текстовый анализатор** начинается после изучения функций и расширяется при изучении файлов, регулярных выражений, генераторов и тестирования.
3. **Анализатор погодных данных** развивается в модулях 6–10 и объединяет ООП, исключения, пакеты, файлы, даты, API и графики.
4. **Планировщик путешествий** начинается в модуле 10 и становится итоговой интеграционной работой в модулях 11–12.

## Хранение кода проектов

Условия заданий размещаются рядом с теорией:

```text
04-Loops/project_tasks.md
```

Рабочий код остаётся в общей папке проекта:

```text
Projects/01-Calculator/calculator.py
```

Каждый следующий этап изменяет текущую версию проекта. Копии проекта внутри учебных модулей не создаются.

## Критерии завершения этапа

Проектный этап считается завершённым, если:

1. реализована обязательная возможность;
2. программа запускается обычным способом;
3. открытые проверки проходят;
4. обработаны указанные в задании граничные случаи;
5. студент может объяснить своё решение;
6. уже реализованные возможности проекта продолжают работать.
